# tests

- 定位：测试总目录。
- 边界：围绕当前 session/message 架构组织验收与文档守卫测试。
- 维护：新测试要先写明覆盖哪一层，避免回到按阶段堆脚本的旧习惯。

## 测试分层

- `acceptance/`：当前必须稳定通过的主链回归。
- `unit/`：工程守卫与小粒度验证。
- `e2e/`、`integration/`：预留目录，当前未承载主线用例。

## 文件清单

| 文件 | 地位 | 功能 |
| --- | --- | --- |
| `README.md` | 目录地图 | 解释当前目录下有哪些成员以及它们各自做什么。 |
| `__init__.py` | 包声明 | 保持测试目录可被 Python 识别。 |
| `conftest.py` | 测试配置 | 集中放置 pytest 共享配置。 |

## 子目录

| 子目录 | 地位 | 功能 |
| --- | --- | --- |
| `acceptance` | 子模块目录 | 现行验收测试目录。 |
| `e2e` | 子模块目录 | 端到端测试预留目录。 |
| `integration` | 子模块目录 | 集成测试预留目录。 |
| `unit` | 子模块目录 | 单元测试目录。 |
