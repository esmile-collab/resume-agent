# 测试与回滚机制

本文档定义测试 Agent 的职责、测试流程和回滚机制。

---

## 1. 测试 Agent 职责

### 1.1 环境隔离
- 为每个测试创建独立的虚拟环境
- 确保测试环境与开发环境分离
- 测试完成后清理环境

### 1.2 验收测试
- 执行验收测试用例
- 生成测试报告
- 记录测试结果

### 1.3 问题定位
- 测试失败时定位问题原因
- 区分代码问题 / 测试问题 / 环境问题
- 提供详细的问题报告

### 1.4 版本回滚
- 维护稳定的版本基线
- 测试失败时回滚到稳定版本
- 保留回滚历史和原因

## 2. 环境隔离机制

### 2.1 虚拟环境创建

```bash
#!/bin/bash
# scripts/create_test_env.sh

set -e

VENV_DIR=".venv_test_$(date +%s)"

echo "创建测试环境: $VENV_DIR"
python -m venv "$VENV_DIR"

echo "激活测试环境"
source "$VENV_DIR/bin/activate"

echo "安装依赖"
pip install --upgrade pip
pip install -e .

echo "安装测试依赖"
pip install pytest pytest-cov pytest-html pytest-asyncio

echo "保存环境信息"
echo "$VENV_DIR" > .test_env_id

echo "✓ 测试环境创建完成: $VENV_DIR"
```

### 2.2 虚拟环境清理

```bash
#!/bin/bash
# scripts/cleanup_test_env.sh

if [ -f .test_env_id ]; then
    VENV_DIR=$(cat .test_env_id)
    echo "清理测试环境: $VENV_DIR"
    rm -rf "$VENV_DIR"
    rm .test_env_id
    echo "✓ 测试环境已清理"
else
    echo "未找到测试环境"
fi
```

## 3. 测试流程

### 3.1 完整测试流程

```
1. 准备阶段
   ├── 创建测试环境
   ├── 安装依赖
   └── 准备测试数据

2. 执行阶段
   ├── 运行验收测试
   ├── 收集测试结果
   └── 生成测试报告

3. 分析阶段
   ├── 分析测试结果
   ├── 定位失败原因
   └── 生成问题报告

4. 决策阶段
   ├── 通过 → 合并代码，创建 tag
   └── 不通过 → 回滚版本，通知开发
```

### 3.2 测试执行脚本

```bash
#!/bin/bash
# scripts/run_acceptance.sh

set -e

MODULE=${1:-"all"}
REPORT_DIR="test_reports/$(date +%Y%m%d_%H%M%S)"
mkdir -p "$REPORT_DIR"

echo "=== 运行验收测试 ==="
echo "模块: $MODULE"
echo "报告目录: $REPORT_DIR"

# 运行测试
if [ "$MODULE" = "all" ]; then
    pytest tests/acceptance/ -v \
        --html="$REPORT_DIR/report.html" \
        --cov=src \
        --cov-report="$REPORT_DIR/coverage.xml" \
        --junitxml="$REPORT_DIR/junit.xml"
else
    pytest "tests/acceptance/test_m${MODULE}.py" -v \
        --html="$REPORT_DIR/report.html" \
        --cov=src \
        --cov-report="$REPORT_DIR/coverage.xml" \
        --junitxml="$REPORT_DIR/junit.xml"
fi

# 检查结果
if [ $? -eq 0 ]; then
    echo "✓ 测试通过"
    echo "报告: $REPORT_DIR/report.html"
else
    echo "✗ 测试失败"
    echo "报告: $REPORT_DIR/report.html"
    exit 1
fi
```

## 4. 回滚机制

### 4.1 Git 版本管理

```bash
# 阶段完成时创建 tag
git tag -a stage-v1 -m "Stage 1 完成: 数据层 + 最小 CLI"

# 查看所有 tag
git tag -l

# 查看tag详情
git show stage-v1

# 推送 tag 到远程
git push origin stage-v1
```

### 4.2 回滚流程

```bash
#!/bin/bash
# scripts/rollback_stage.sh

set -e

CURRENT_STAGE=${1:-"$(git describe --tags --abbrev=0)"}

echo "=== 回滚到上一个稳定版本 ==="
echo "当前版本: $CURRENT_STAGE"

# 获取上一个 tag
PREV_TAG=$(git tag -l "stage-v*" | sort -V | grep -B 1 "$CURRENT_STAGE" | head -1)

if [ -z "$PREV_TAG" ]; then
    echo "未找到上一个稳定版本"
    exit 1
fi

echo "回滚到: $PREV_TAG"

# 确认
read -p "确认回滚? (y/N) " -n 1 -r
echo
if [[ ! $REPLY =~ ^[Yy]$ ]]; then
    echo "取消回滚"
    exit 0
fi

# 非破坏性回滚：创建回滚分支
git checkout -b "rollback-$(date +%Y%m%d_%H%M%S)" "$PREV_TAG"

# 标记当前失败的 tag（可选）
git tag -a "$CURRENT_STAGE-failed" -m "回滚: 验收测试失败"

echo "✓ 已回滚到 $PREV_TAG"
echo "失败的 tag: $CURRENT_STAGE-failed"
```

### 4.3 回滚记录

```markdown
# 回滚记录 - stage-v2

**回滚时间**: 2026-02-27 15:00:00
**回滚版本**: stage-v2 → stage-v1

|---|---|
| test_generate_low_match | AssertionError: expect await_risk_ack=True, got False |

- M2 模块需要重新开发
- 依赖 M2 的 M3-stub 需要重新测试
```

## 5. 问题定位流程

### 5.1 测试失败分析

```bash
#!/bin/bash
# scripts/diagnose_test_failure.sh

TEST_FILE=$1
REPORT_DIR="failure_analysis_$(date +%Y%m%d_%H%M%S)"
mkdir -p "$REPORT_DIR"

echo "=== 测试失败分析 ==="
echo "测试文件: $TEST_FILE"
echo "分析目录: $REPORT_DIR"

# 1. 详细输出
echo "1. 获取详细输出..."
pytest "$TEST_FILE" -vv --tb=long 2>&1 | tee "$REPORT_DIR/verbose_output.txt"

# 2. 最小化输出
echo "2. 获取失败摘要..."
pytest "$TEST_FILE" --tb=no 2>&1 | tee "$REPORT_DIR/summary.txt"

# 3. 调试日志
echo "3. 获取调试日志..."
pytest "$TEST_FILE" --log-level=DEBUG --log-cli 2>&1 | tee "$REPORT_DIR/debug_log.txt"

# 4. 覆盖率报告
echo "4. 生成覆盖率报告..."
pytest "$TEST_FILE" --cov=src --cov-report="$REPORT_DIR/coverage_html" --cov-report=term

# 5. 生成问题报告
cat > "$REPORT_DIR/problem_report.md" << EOF
# 测试失败报告

**测试文件**: $TEST_FILE
**分析时间**: $(date)

## 失败摘要

$(cat "$REPORT_DIR/summary.txt")

## 详细错误

$(cat "$REPORT_DIR/verbose_output.txt" | grep -A 20 "FAILED")

## 可能原因

TODO: 需要人工分析

EOF

echo "分析完成: $REPORT_DIR"
echo "问题报告: $REPORT_DIR/problem_report.md"
```

### 5.2 问题分类

| 问题类型 | 特征 | 处理方式 |
|---|---|---|
| **代码问题** | 测试正确，代码有 bug | 回滚，通知开发修复 |
| **测试问题** | 代码正确，测试有误 | 修复测试，重新运行 |
| **环境问题** | 依赖缺失、配置错误 | 修复环境，重新运行 |
| **接口问题** | 接口定义不匹配 | 更新接口文档，重新开发 |

### 5.3 问题报告模板

```markdown
# 测试失败报告

**模块**: M2 - 路由与状态机
**测试时间**: 2026-02-27 14:30:00
**Git Commit**: def456 (feat(m2): implement router logic)

## 失败摘要

2 个测试用例失败：
- `test_generate_low_match`
- `test_ingest_jd_routing`

## 详细错误

### test_generate_low_match

```
src/routes/router.py:123: in route
    assert decision.await_risk_ack == True
AssertionError: assert False == True
```

**原因**: `handle_generate` 函数中低匹配时未设置 `await_risk_ack`

**修复建议**:
```python
# 在 handle_generate 中添加
if match_level == MatchLevel.LOW:
    return RouteDecision(
        state=TaskState.SCORED,
        await_risk_ack=True,  # ← 添加这行
        message="..."
    )
```

### test_ingest_jd_routing

```
src/routes/router.py:89: in route
    AttributeError: 'NoneType' object has no attribute 'decisions'
```

**原因**: `jd_splitter` 返回 None，未处理空输入

**修复建议**:
```python
# 在 route_task 中添加
split_result = jd_splitter(jd_payload)
if split_result is None:
    return RouteDecision(
        state=TaskState.PENDING,
        message="JD 解析失败，请检查 JD 格式"
    )
```

## 问题类型

- [x] 代码问题
- [ ] 测试问题
- [ ] 环境问题
- [ ] 接口问题

## 建议处理方式

1. 回滚到 stage-v1
2. 开发 Agent 修复上述两个问题
3. 重新提交验收测试
```

## 7. 持续集成（可选）

### 7.1 GitHub Actions 配置

```yaml
# .github/workflows/acceptance.yml
name: Acceptance Tests

on:
  pull_request:
    branches: [main]
  push:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
    - uses: actions/checkout@v3

    - name: Set up Python
      uses: actions/setup-python@v4
      with:
        python-version: '3.11'

    - name: Install dependencies
      run: |
        pip install -e .
        pip install pytest pytest-cov pytest-html

    - name: Run acceptance tests
      run: |
        pytest tests/acceptance/ -v \
          --html=report.html \
          --cov=src \
          --junitxml=junit.xml

    - name: Upload test results
      uses: actions/upload-artifact@v3
      with:
        name: test-results
        path: |
          report.html
          junit.xml
          .coverage
```

### 7.2 自动回滚规则

```yaml
