版本：v1.0  
日期：2026-03-01

## 1. 适用范围

本说明用于本地运行 `Resume Agent` 项目，覆盖：

1. 环境初始化
2. CLI 端到端使用
3. Local Web API（`POST /run`）使用

## 5. CLI 端到端完整示例

示例使用仓库内 fixture 文件：

1. `tests/fixtures/resume/sample_resume_001.txt`
2. `tests/fixtures/jd/sample_jd_001.txt`
3. `tests/fixtures/jd/sample_jd_002.txt`

### Step 1: 创建项目

```bash
resume_agent project init \
  --name "demo-project" \
  --cycle "2026秋招" \
  --resume tests/fixtures/resume/sample_resume_001.txt
```

输出示例：

```text
✓ 项目已创建: abc12345
```

记录 `project_id`（如 `abc12345`）。

### Step 2: 导入 JD（生成分配预览）

```bash
resume_agent project ingest-jd \
  --project abc12345 \
  --jd tests/fixtures/jd/sample_jd_001.txt \
  --jd tests/fixtures/jd/sample_jd_002.txt \
  --format json
```

返回 JSON 中记录 `plan_id`。

### Step 3: 确认分配计划

```bash
resume_agent project confirm-allocation \
  --project abc12345 \
  --plan <plan_id> \
  --format json
```

返回中会包含 `task_cards`，记录其中一个 `task_card_id`。

### Step 4: 运行卡片生成

```bash
resume_agent card run \
  --project abc12345 \
  --card <task_card_id> \
  --out .data/demo_report.md \
  --format json
```

若返回低匹配风险确认提示，再执行：

```bash
resume_agent card run \
  --project abc12345 \
  --card <task_card_id> \
  --out .data/demo_report.md \
  --risk-ack \
  --format json
```

## 6. API（POST /run）使用说明

`/run` 使用单端点 + `action` 分发，当前支持：

1. `project.init`
2. `project.ingest_jd`
3. `project.confirm_allocation`
4. `card.add_jd`
5. `card.run`
6. `dialog.append`（M7 对话记录/压缩）

### 6.1 创建项目

```bash
curl -X POST "http://127.0.0.1:8000/run" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "project.init",
    "name": "api-demo",
    "cycle": "2026秋招",
    "resume_text": "示例简历文本"
  }'
```

### 6.2 导入 JD

```bash
curl -X POST "http://127.0.0.1:8000/run" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "project.ingest_jd",
    "project_id": "<project_id>",
    "jd_texts": ["JD 文本 A", "JD 文本 B"],
    "source_files": ["a.txt", "b.txt"]
  }'
```

### 6.3 确认分配

```bash
curl -X POST "http://127.0.0.1:8000/run" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "project.confirm_allocation",
    "project_id": "<project_id>",
    "plan_id": "<plan_id>"
  }'
```

### 6.4 运行卡片

```bash
curl -X POST "http://127.0.0.1:8000/run" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "card.run",
    "project_id": "<project_id>",
    "task_card_id": "<task_card_id>",
    "risk_ack": false
  }'
```

### 6.5 追加对话（M7）

```bash
curl -X POST "http://127.0.0.1:8000/run" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "dialog.append",
    "project_id": "<project_id>",
    "role": "user",
    "content": "补充一个关键事实",
    "facts": ["负责增长实验闭环"]
  }'
```

## 7. 运行后文件与日志位置

每个项目的数据在：

```text
.data/artifacts/<project_id>/
```

关键文件：

1. `resume/base_resume_v1.txt`：基础简历
2. `jd/*.txt`：JD 文本
3. `plans/*.json`：分配预览计划
4. `state/task_cards.json`：任务卡状态
5. `outputs/*.md`：生成产物
6. `runs/runs.jsonl`：运行日志
7. `runs/telemetry.jsonl`：M7 埋点日志
8. `state/dialog_messages.json`：最近对话消息
9. `state/dialog_summary.json`：长对话压缩摘要

## 9. 常见问题排查

### Q1: `resume_agent: command not found`

原因：未激活虚拟环境或未安装 editable 包。  
处理：

```bash
source .venv/bin/activate
python -m pip install -e .
```

### Q2: `ModuleNotFoundError: src`（pytest 导入失败）

处理：

1. 在项目根目录执行测试
2. 使用虚拟环境内 pytest：`.venv/bin/pytest tests/acceptance/ -v`
3. 确认存在 `tests/conftest.py` 路径注入逻辑

### Q3: `No module named 'fastapi'` 或 `httpx`

处理：

```bash
source .venv/bin/activate
python -m pip install -e .
```

### Q4: `python` 与 `pip` 指向不同版本

处理（强烈建议）：

```bash
rm -rf .venv
python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
```
