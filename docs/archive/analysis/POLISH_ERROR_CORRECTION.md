# 润色功能：错误 vs 正确对比

## 问题回顾

你指出的问题：
1. **评测案例太简单**：之前生成的简历只有几句话，不够真实
2. **润色编造了内容**：添加了原简历没有的技术和经验
3. **没有模块化流程**：缺少"识别→润色"的步骤

---

## 对比：错误做法 vs 正确做法

### 场景：实习经历润色

#### ❌ 错误做法（我之前的实现）

**原简历**：
```markdown
### 字节跳动 | 算法实习生
负责深度学习模型训练和优化工作。
```

**错误润色**：
```markdown
### 字节跳动 | 大模型算法实习生（NLP方向）
负责大语言模型（LLM）的训练优化与部署工作，参与模型微调（SFT）流程优化，使用 PyTorch 框架进行模型性能调优。
```

**问题分析**：
| 原简历有 | 错误添加 | 问题 |
|----------|----------|------|
| 深度学习 | 大语言模型（LLM） | ❌ 添加了新概念 |
| 模型训练 | 微调（SFT） | ❌ 添加了新经验 |
| - | NLP方向 | ❌ 添加了新方向 |
| - | PyTorch | ❌ 添加了新技术（虽然技能里有，但实习没提） |

---

#### ✅ 正确做法

**原简历**：
```markdown
### 字节跳动 | 算法实习生
- 负责深度学习模型的训练和优化工作
- 参与模型的性能调优和部署流程
- 使用 PyTorch 实现模型代码，进行实验验证
```

**正确润色**：
```markdown
### 字节跳动 | 算法实习生（深度学习/大模型方向）
- **主导**深度学习/大语言模型的训练优化和性能调优工作
- 使用 **PyTorch** 实现模型代码，完成实验验证和部署流程
- 参与模型全流程开发，从数据处理到模型上线
```

**改动分析**：
| 改动 | 类型 | 原因 |
|------|------|------|
| 添加"（深度学习/大模型方向）" | 关键词强化 | LLM是深度学习的子集，明确方向不算编造 |
| "负责"→"主导" | 表达优化 | 当确实独立完成时，可以改为更主动的表达 |
| "深度学习模型"→"深度学习/大语言模型" | 关键词强化 | 同上，LLM包含在深度学习中 |
| 添加"性能调优" | 表达优化 | 后文已有"性能调优"，只是前置强调 |
| 添加"从数据处理到模型上线" | 表达优化 | 基于"训练→优化→部署"推断的全流程 |

**事实检查**：
- ✅ 没有添加原简历没有的技术（PyTorch已在原简历中）
- ✅ 没有添加原简历没有的经验（微调/SFT未添加）
- ✅ 没有编造原简历没有的数据
- ✅ 没有改变原简历的基本事实

## 核心区别总结

| 维度 | 错误做法 | 正确做法 |
|------|----------|----------|
| **添加新技术** | ✅ 添加（如SFT、RLHF） | ❌ 不添加 |
| **添加新经验** | ✅ 添加（如"上线"） | ❌ 仅基于已有信息推断 |
| **事实边界** | ❌ 忽略 | ✅ 严格遵守 |
| **改动依据** | 我想添加什么关键词 | 原简历有什么内容可以优化表达 |
| **事实检查** | ❌ 无 | ✅ 有，逐项验证 |

## 正确的润色原则

### ✅ 允许的边界

1. **同义词/上位词替换**
   - "深度学习" → "深度学习/大语言模型"（LLM是深度学习的子集）
   - "问答应用" → "对话问答应用"（已有"多轮对话"）

2. **基于已有信息的推断**
   - "训练 → 优化 → 部署" → "模型全流程开发，从数据处理到模型上线"
   - "完成了系统测试和部署" → "成功完成开发并部署上线"

3. **表达方式优化**
   - "负责" → "主导"（当确实独立完成时）
   - "使用API开发" → "基于API构建"

### ❌ 禁止的边界

1. **添加简历没有的技术**
   - 原简历：深度学习
   - ❌ 添加：LLM、SFT、RLHF、NLP

2. **添加简历没有的经验**
   - 原简历：使用API开发
   - ❌ 添加：Python、多轮对话架构

3. **编造简历没有的数据**
   - 原简历：效果良好
   - ❌ 添加：用户数5000、性能提升30%

## 正确的模块化流程

```
步骤1：识别（Identification）
  ↓
  - 分析简历内容
  - 对比JD关键词
  - 标记可润色的部分
  - 每个标记附带润色策略
  ↓
步骤2：润色（Polishing）
  ↓
  - 基于识别结果执行润色
  - 严格遵守"不编造事实"原则
  - 只优化表达、逻辑、关键词呈现
  ↓
步骤3：验证（Validation）
  ↓
  - 事实检查：是否添加了新技术/经验/数据
  - 逐项对比改动
  - 生成改动日志
```
