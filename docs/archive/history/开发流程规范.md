# 简历 Agent 开发流程规范

版本：v1.0
日期：2026-02-27
角色分工：
- 开发 Agent：负责编码实现
- 测试 Agent（监工）：负责环境隔离、测试验收、问题定位、版本回滚

---

## 1. 开发原则

### 1.1 模块化开发
- 每个模块独立开发、独立验收
- 模块之间通过明确的接口定义交互
- 先做 stub 版本打通流程，再实现真实逻辑

### 1.2 验收驱动
- 每个模块开发前明确验收标准
- 开发完成后必须通过所有验收测试
- 不通过验收不得进入下一阶段

### 1.3 可回滚机制
- 每个 Stage 完成后创建 Git tag
- 测试失败时回滚到上一个稳定版本
- 保留所有测试用例和测试结果

---

## 2. 开发阶段划分

```
Stage 0: 环境准备
├── 创建项目结构
├── 配置开发环境
└── 验收：项目可运行、测试可执行

Stage 1: 数据层 + 最小 CLI
├── M0: 工程脚手架
├── M1: SQLite + 本地文件持久化
└── M1.5: 最小 CLI（project init/list）

Stage 2: 工具 Stub + 路由骨架
├── M3-stub: Domain Tools 的 stub 版本
└── M2: 路由与状态机

Stage 3: 真实工具实现
└── M3-real: Domain Tools 的 LLM 版本

Stage 4: 完整编排
├── M4: 端到端编排
└── M5: 完整 CLI 命令集

Stage 5: 稳定性
└── M7: 埋点 + 回归测试
```

---

## 3. 开发流程

### 3.1 单个模块开发流程

```
1. 开发前
   ├── 测试 Agent 提供验收标准文档
   ├── 创建 feature 分支：feature/<module-name>
   └── 确认接口定义和数据结构

2. 开发中
   ├── 开发 Agent 实现
   ├── 本地自测
   └── 提交 PR/MR

3. 验收
   ├── 测试 Agent 创建隔离环境
   ├── 运行验收测试
   ├── 记录测试结果
   └── 通过/不通过决策

4. 后处理
   ├── 通过：合并到 main，创建 tag
   └── 不通过：回滚，开发 Agent 修复后重新验收
```

### 3.2 阶段完成流程

```
1. 所有模块验收通过
2. 集成测试
3. 创建 Git tag：stage-v<stage-number>
4. 生成测试报告
5. 进入下一阶段
```

## 5. 测试 Agent 职责

### 5.1 环境隔离
```bash
# 为每个测试创建独立环境
python -m venv .venv_test
source .venv_test/bin/activate
pip install -e .
```

### 5.2 验收测试
```bash
# 运行验收测试
pytest tests/acceptance/test_m1.py -v

# 生成测试报告
pytest tests/acceptance/test_m1.py --html=report_m1.html
```

### 5.3 问题定位
```bash
# 测试失败时
pytest tests/acceptance/test_m1.py -vv --tb=short

# 生成详细日志
pytest tests/acceptance/test_m1.py --log-level=DEBUG
```

### 5.4 版本回滚
```bash
# 非破坏性回滚：创建回滚分支
git checkout -b rollback-<stage-name> stage-v1
# 如有需要，可删除失败的 tag（在确认分支安全后）
git tag -d stage-v2  # 仅在确认可删除时执行
```

## 6. Git 规范

### 6.1 分支命名
```
feature/<module-name>     # 功能开发
fix/<module-name>         # Bug 修复
test/<module-name>        # 测试相关
```

### 6.2 Commit 格式
```
<type>(<scope>): <subject>

<body>

<footer>
```

type: feat / fix / test / docs / refactor
scope: 模块名（m0/m1/m2等）
subject: 简短描述（50字内）
body: 详细说明
footer: 相关 issue / PR 链接

示例：
```
feat(m1): implement Project CRUD

- Create project with name and cycle
- Query project by ID
- List all projects

Closes #1
```

### 6.3 Tag 命名
```
stage-v<stage-number>     # 阶段完成
v<major>.<minor>.<patch>   # 版本发布
```

## 7. 质量标准

### 7.1 代码质量
- 所有函数必须有类型注解
- 关键函数必须有 docstring
- 单元测试覆盖率 > 80%

### 7.2 测试标准
- 每个模块至少 3 个测试用例
- 必须包含正常流程和异常流程
- 测试必须是可重复的

### 7.3 文档标准
- 每个模块必须有 README
- 接口变更必须更新 API 文档
- 重要决策必须记录 ADR（Architecture Decision Record）

## 8. 应急预案

### 8.1 开发阻塞
```
1. 标记模块状态为 blocked
2. 记录阻塞原因
3. 切换到其他模块或等待
4. 阻塞解除后恢复开发
```

### 8.2 测试失败
```
1. 记录失败的测试用例
2. 定位失败原因（代码/测试/环境）
3. 回滚到上一个稳定版本
4. 开发 Agent 修复后重新测试
```

### 8.3 版本回滚
```
1. 标记失败的 tag
2. 回滚到上一个稳定 tag
3. 清理环境
4. 重新开始该阶段
```
