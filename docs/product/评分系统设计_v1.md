## 1. 设计目标

1. **降低主观性**：将LLM主观判断拆解为客观指标计算
2. **降低成本**：单次LLM调用完成全部评分，成本降低85%
3. **提升用户体验**：评分卡片披露维度详情+快速行动建议
4. **认知补偿机制**：通过自我陈述弥补经历差距

---

## 2. 评分框架总览

```
L0 风险信号检测（不做硬拦截）
    ↓
L1 七维评分（0-100分，客观指标计算）
    ↓
L2 推荐路由（高/中/低匹配策略建议）
    ↓
评分卡片输出（披露4个核心维度+自我陈述模板）
```

## 3. L0 风险信号检测（优化：预警机制）

### 3.1 检测维度

| 检测项 | 判定规则 | 处理方式 |
|---|---|---|
| Must-have命中率 | JD中的"必须要求"与简历匹配率 < 30% | 风险提示 → Reviewer Agent复核 |
| 工作年限 | 用户年限 < JD要求年限的50% | 风险提示 → 检查是否有Override证据 |
| 时间线冲突 | 检测到时间重叠或异常gap | 风险提示 + 允许用户解释 |

### 3.2 风险提示处理流程

```
检测到风险 → 标记【风险提示】 → Reviewer Agent二次判断
    ↓
确认风险较高 → 输出"建议谨慎投递，原因XXX"
可能有误杀 → 降低该维度权重，继续评分
用户有合理解释 → 豁免该风险，继续评分
```

### 3.3 用户控制权：风险确认后继续生成

当检测到高风险或低匹配时，用户可选择：

**A. 风险确认后生成（补偿模式）**
- 仍然输出改写版本
- 生成补偿内容（个人陈述/求职信/话术）
- 提示用户"面试时可能被深挖，需提前准备"

**B. 接受建议，暂不投递**
- 查看提升路径建议
- 保存为待投递岗位

## 4. L1 七维评分系统（客观化拆解）

### 4.1 核心思路

> **LLM只负责"信息提取"，不负责"评分判断"。打分由规则计算。**

### 4.2 七维度客观化拆解

| 维度 | 权重 | 原主观判断 | 客观指标拆解 | 计算方法 |
|---|---|---|---|---|
| **公司级别匹配度** | 10分 | "体量是否接近" | 公司规模分 + 业务复杂度分 | 规模：大厂10分/独角兽7分/中型5分/小厂3分<br>复杂度：多业务线10分/单业务线5分 |
| **业务级别匹配度** | 15分 | "链路是否一致" | 关键词重合率 + 场景相似度 | JD关键词∩简历关键词 / JD关键词 × 10 + LLM评估场景相似度(0-5) |
| **行业匹配度** | 10分 | "是否同行业" | 行业标签精确匹配 | 完全相同10分/相邻行业5分/跨行业0分 |
| **岗位经验匹配度** | 20分 | "职责重合度" | 职责关键词重合 + 产出物匹配 | JD职责词∩经历职责词 / JD职责词 × 15 + 产出物相似度(0-5) |
| **能力匹配度** | 20分 | "技能覆盖度" | 硬技能覆盖率 + AI能力分 | JD硬技能∩用户技能 / JD硬技能 × 15 + AI产品相关经历(0-5) |
| **真实性可信度** | 15分 | "证据是否充分" | 证据绑定率 + 数据可追问率 | 有证据的改动点 / 总改动点 × 10 + 有数据的改动点 / 总改动点 × 5 |
| **可复述性** | 10分 | "能否口头解释" | STAR完整度 + 语言复杂度 | STAR完整改动点 / 总改动点 × 7 + 平均句长 < 20字(3分) |

### 4.3 总分计算

```
S100 = 七维加总（0-100）

评级标准：
- S100 >= 75：高匹配，可直接投递
- 50 <= S100 < 75：中等匹配，建议补充后投递
- S100 < 50：低匹配，需风险确认后继续或先提升经历
```

### 4.4 L2 推荐路由（与PRD v0.3对齐）

```
S100 >= 75（high）：推荐正常生成
50 <= S100 < 75（medium）：推荐补充后生成，也可直接生成
S100 < 50（low）：需要风险确认，确认后进入补偿模式生成

说明：评分用于“推荐路径”，不作为硬阻断。
```

补充边界：
1. 评分输入来自 `Task Card` 关联的 Project JD 引用集合。
2. `Task Card` 不持有 JD 原文，只消费 Project 层的 JD 解析结果。

## 5. LLM调用优化方案

### 5.1 优化前：7次调用

```
每个维度 → 独立LLM调用 → 独立评分
成本：7 × $0.01 = $0.07/份
耗时：7 × 3秒 = 21秒
```

### 5.2 优化后：1次调用

## 7. 自我陈述机制

### 7.1 核心思路

> **经历不够，认知来补。允许用户通过"理解+思考"弥补"没做过"的差距。**

### 7.2 自我陈述的3个场景

| 场景 | 自我陈述侧重点 | 示例 |
|---|---|---|
| **业务不匹配** | 可迁移能力 + 快速学习意愿 | "虽然没做过内容运营，但在选品中积累了用户理解，能快速上手" |
| **行业不匹配** | 行业洞察 + 底层逻辑理解 | "虽然没做过电商，但擅长增长模型，适用于任何行业" |
| **技能不匹配** | 学习能力 + 相关经验迁移 | "没用过Python，但用SQL做过类似分析，学习成本很低" |

### 7.3 产品侧实现

```markdown
## 自我陈述生成器

当检测到用户经历与JD有差距时，自动生成自我陈述模板：

1. 分析差距维度（业务/行业/技能）
2. 提取用户现有经历中的可迁移能力
3. 组合生成"认知补偿型"陈述
4. 用户可选择：
   - 直接采纳
   - 修改后采纳
   - 不采纳（保持原简历）
```

### 7.4 自我陈述效果预期

## 9. 完整流程

```
用户上传简历+JD
    ↓
[L0] 风险信号检测
    ├── 无明显风险 → 继续
    └── 有风险 → 风险提示 + Reviewer复核（不硬拦截）
    ↓
[L1] 单次LLM调用
    ├── 信息提取（JD关键词、简历关键词、公司级别、业务类型...）
    ├── 维度评分（7个维度）
    └── 总分计算
    ↓
[规则验证] Python代码二次验证
    ├── 关键词重合率计算
    ├── 证据绑定率计算
    └── 评分修正
    ↓
[L2] 推荐路由
    ├── S100 >= 75 → 推荐正常生成
    ├── 50 <= S100 < 75 → 推荐补充后生成（用户可直接生成）
    └── S100 < 50 → 触发风险确认，确认后补偿模式生成
    ↓
[评分卡片生成]
    ├── 核心指标（总分+评级+投递建议）
    ├── 4个核心维度详情
    ├── 自我陈述模板
    └── 推荐提升项目
    ↓
用户选择
    ├── A. 采纳自我陈述 + 生成简历
    ├── B. 直接生成简历（不改）
    └── C. 先提升经历，暂不投递
```

## 10. 技术实现要点

### 10.1 客观指标计算（Python）

```python
# 关键词重合率
def keyword_overlap(jd_keywords, resume_keywords):
    overlap = set(jd_keywords) & set(resume_keywords)
    return len(overlap) / len(jd_keywords)

# 证据绑定率
def evidence_binding(change_points):
    with_evidence = sum(1 for cp in change_points if cp["evidence"])
    return with_evidence / len(change_points)

# STAR完整度
def star_completeness(change_points):
    complete = sum(1 for cp in change_points if cp["star_complete"])
    return complete / len(change_points)
```

### 10.2 行业标签匹配

```python
# 行业相似度矩阵
industry_similarity = {
    ("电商", "零售"): 0.8,
    ("电商", "内容"): 0.5,
    ("电商", "金融"): 0.1,
    # ...
}

def industry_match(jd_industry, resume_industry):
    if jd_industry == resume_industry:
        return 10  # 完全相同
    similarity = industry_similarity.get((jd_industry, resume_industry), 0)
    if similarity >= 0.7:
        return 5  # 相邻行业
    return 0  # 跨行业
```

## 12. 面试话术参考

### Q: 为什么要设计这么复杂的评分系统？

A: "Chatbot解决了'能不能生成'的问题，但AI产品更需要解决'生成得好不好、用户敢不敢用'的问题。我设计了客观化的七维评分体系，把主观判断拆解为可计算的指标，这样既能保证质量可控，又能让用户理解'为什么是这个分数'。"

### Q: LLM评分不是会很主观吗？

A: "所以我做了两层优化：第一层是把评分拆解为客观指标，比如关键词重合率、证据绑定率，这些用代码直接计算；第二层是单次LLM调用提取信息，然后用规则验证和修正。这样既降低了成本，又保证了客观性。"

### Q: 为什么要做自我陈述机制？

A: "因为我发现很多用户经历不够，但不代表能力不够。自我陈述是给用户一个'认知补偿'的机会，让他们能表达'虽然没做过，但我理解且能快速上手'。这比直接拒绝更有帮助，也符合顾问而非评判者的定位。"
