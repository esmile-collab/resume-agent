## 1. 设计目标

1. **聚焦校招场景**：针对实习生和应届毕业生的特殊需求
2. **实习优先**：实习经历 > 项目经历 > 专业对口（符合实际招聘）
3. **统一指标**：所有岗位使用统一的软性指标，HR能理解
4. **具体可评**：软性指标从抽象概念转为具体可观察的行为

## 2. 硬性指标重新设计

### 2.1 优先级调整

```
实习经历（最重要）> 项目经历 > 技术实践 > 学历/专业 > 其他
```

**原因**：
- 实习经历 = 真实工作环境验证，含金量最高
- 项目经历 = 证明动手能力，比课程重要
- 技术实践 = 看项目中用了什么技术，不看重课程成绩

### 2.2 新维度设计

| 维度 | 权重 | 评估方式 | 具体标准 |
|---|---|---|---|---|
| **实习经历** | 25% | 看实习质量和数量 | 一线大厂=100，独角兽=85，中型=70，初创=50，无=20 |
| **项目经历** | 20% | 看项目完整性和技术含量 | 完整上线项目=100，课程设计=60，想法阶段=30，无=0 |
| **技术实践** | 15% | 看项目中用的技术栈是否匹配 | 完全匹配=100，部分匹配=70，不匹配=30 |
| **学历层次** | 10% | 学校层次 | 985/海外top=100，211=85，双非一本=70，其他=50 |
| **专业对口** | 10% | 专业相关性 | 完全对口=100，相关=70，跨专业=40 |
| **在校成绩** | 5% | GPA/排名 | 前10%=100，前30%=80，前50%=60，其他=40 |
| **竞赛获奖** | 5% | 竞赛级别和含金量 | 国际级=100，国家级=85，省级=70，校级=50 |
| **英语水平** | 5% | 英语证书 | 雅思7+/托福100+=100，六级500+=85，六级425+=70 |
| **开源贡献** | 3% | GitHub/开源项目 | 有且活跃=100，有一般=70，无=30 |
| **稳定性** | 2% | 毕业时间和可实习时长 | 完全满足=100，基本满足=70，有冲突=40 |

### 2.3 技术实践评估方式（重点改进）

**旧方式**：看课程学习情况（数据结构、算法等课程成绩）
**新方式**：看项目中是否涉及相关技术

**示例**：
```
JD: 前端实习生，要求 React/Vue

评估逻辑：
- 检查简历中的项目经历
- 找到是否用了 React/Vue
- 用了且是核心 = 100分
- 用了但是辅助 = 70分
- 完全没用 = 30分（但项目中有 JS 可以给到 50分）
```

```python
def assess_technical_practice(jd_tech_requirements, resume_projects):
    """
    技术实践评估：看项目中是否用到 JD 要求的技术

    不是看课程，是看项目！
    """
    score = 0
    evidence = []

    for project in resume_projects:
        for tech in jd_tech_requirements:
            if tech in project["tech_stack"]:
                # 找到了！
                if tech in project["core_techs"]:
                    score = max(score, 100)
                    evidence.append(f"项目 {project['name']} 中 {tech} 是核心技术")
                else:
                    score = max(score, 70)
                    evidence.append(f"项目 {project['name']} 中使用了 {tech}")
            elif any(is_similar(t, tech) for t in project["tech_stack"]):
                # 找到相似技术
                score = max(score, 50)
                evidence.append(f"项目 {project['name']} 中用了 {tech} 的相似技术")

    return {
        "score": score if score > 0 else 30,
        "evidence": evidence if evidence else ["项目中未找到相关技术"]
    }
```

## 3. 软性指标重新设计（统一版本，不区分岗位）

### 3.1 设计思路

**问题**：
- 技术岗的"技术深度""代码质量"等指标，HR 看不懂，也不关心
- 用户反馈："我不懂技术，HR 也不懂技术，不要分技术和非技术了"

**解决方案**：
- 使用统一的通用能力指标，HR 能理解
- 所有岗位（技术/非技术）使用同一套评分维度
- 简化流程，不需要判断岗位类型

## 7. 软性指标重新设计（统一版本，不区分岗位）

### 7.1 设计思路

**问题**：技术岗的"技术深度""代码质量"等指标，HR 看不懂，也不关心。

**解决方案**：统一使用 HR 能理解的通用能力指标。

### 7.2 统一软性指标（6个）

| 维度 | 权重 | HR 能理解的评估焦点 | 具体评分标准 |
|---|---|---|---|
| **学习能力** | 25% | 新技能的掌握速度和广度 | 快速掌握多技能=100<br>正常掌握=80<br>较慢=60 |
| **执行能力** | 25% | 把事情做成的能力 | 主导完成项目=100<br>参与完成=80<br>辅助完成=60 |
| **沟通表达** | 15% | 表达清晰度和逻辑性 | 表达清晰=100<br>基本清晰=70<br>表达混乱=40 |
| **数据意识** | 15% | 用数据证明成果的能力 | 量化成果=100<br>有数据意识=80<br>无数据意识=40 |
| **稳定性** | 10% | 职业规划的清晰度 | 规划清晰=100<br>基本稳定=70<br>频繁跳方向=40 |
| **适配度** | 10% | 与岗位/团队的匹配度 | 高度匹配=100<br>基本匹配=70<br>不太匹配=40 |

### 7.3 评分标准详细说明

#### 学习能力（25%）

**HR 理解**：这个候选人能快速学会新东西吗？

| 分数 | 标准 | 证据示例 |
|---|---|---|
| 100分 | 快速掌握多项新技能 | 3个月掌握3项新技能<br>自学难度高的技术 |
| 80分 | 正常掌握新技能 | 按计划学习课程/技术<br>在项目中应用 |
| 60分 | 较慢掌握新技能 | 学习时间比预期长<br>需要额外指导 |
| 40分 | 学习困难 | 技能掌握不扎实<br>需要反复指导 |

#### 执行能力（25%）

**HR 理解**：这个候选人能把事情做成吗？

| 分数 | 标准 | 证据示例 |
|---|---|---|
| 100分 | 主导完成完整项目 | 从0到1完成项目上线<br>独立负责核心模块 |
| 80分 | 参与完成项目 | 参与项目并负责重要部分<br>独立完成分配任务 |
| 60分 | 辅助完成项目 | 协助团队完成支持工作<br>按指令完成任务 |
| 40分 | 只有想法未落地 | 提出想法但未实施<br>参与讨论但无产出 |

#### 沟通表达（15%）

**HR 理解**：这个候选人能说清楚事情吗？

| 分数 | 标准 | 证据示例 |
|---|---|---|
| 100分 | 表达清晰，逻辑严密 | 项目描述清晰<br>回答问题有条理 |
| 70分 | 表达基本清晰 | 能说明白项目内容<br>逻辑基本通顺 |
| 50分 | 表达一般 | 描述不够清晰<br>逻辑有些混乱 |
| 40分 | 表达混乱 | 说不清楚做了什么<br>逻辑混乱 |

#### 数据意识（15%）

**HR 理解**：这个候选人懂得用数据说话吗？

| 分数 | 标准 | 证据示例 |
|---|---|---|
| 100分 | 量化成果，用数据指导决策 | "将留存率提升30%"<br>"A/B测试数据显示方案A更好" |
| 80分 | 有数据意识，偶尔用数据 | 提到一些数据<br>但不够深入 |
| 60分 | 提到数据但不够深入 | 说"效果很好"但无具体数据 |
| 40分 | 完全没有数据意识 | 全部是定性描述<br>无量化思维 |

#### 稳定性（10%）

**HR 理解**：这个候选人会稳定做下去吗？

| 分数 | 标准 | 证据示例 |
|---|---|---|
| 100分 | 职业规划清晰，长期意愿 | "希望在XX领域深耕"<br>"3-5年职业规划明确" |
| 70分 | 基本稳定，短期意愿 | 愿意先尝试这个方向 |
| 40分 | 不稳定，频繁跳方向 | 短期内多次换方向<br>职业目标模糊 |

#### 适配度（10%）

**HR 理解**：这个候选人适合这个岗位/团队吗？

| 分数 | 标准 | 证据示例 |
|---|---|---|
| 100分 | 高度匹配，价值观契合 | 个人兴趣与岗位高度契合<br>对公司文化有了解 |
| 70分 | 基本匹配，可以适应 | 具备岗位要求的能力<br>愿意学习 |
| 40分 | 不太匹配，需要调整 | 兴趣不匹配<br>能力明显不足 |

## 8. 主流程（简化版，无岗位路由）

### 8.1 流程图

```
输入: JD + 简历
    ↓
【步骤 1】LLM 第一次调用（参数提取 + 软性评分）
    ├── 硬性指标参数提取（实习、项目、技术实践等）
    └── 软性指标评分（6个统一维度）
    ↓
【步骤 2】规则评分计算
    ├── 根据提取的参数计算硬性指标分数
    └── 归一化处理
    ↓
【步骤 3】LLM 第二次调用（综合报告生成）
    ├── 整合硬性分数 + 软性分数
    └── 生成用户友好的综合报告
    ↓
输出: 评分报告（总分 + 维度分析 + 建议）
```

### 8.2 关键变化

| 变化项 | v2.1 之前 | v2.1 当前 |
|---|---|---|
| 岗位判断 | 需要关键词路由判断岗位类型 | 不需要判断，统一处理 |
| 软性指标 | 技术岗/非技术岗两套指标 | 统一6个指标，HR能理解 |
| LLM 调用 | 可能需要根据岗位类型切换 Prompt | 单一 Prompt，简化流程 |

## 10. 与之前版本对比

| 对比项 | v2.0 | v2.1（当前） |
|---|---|---|
| **硬性指标优先级** | 学历 > 专业 > 实习 | **实习 > 项目 > 技术实践** |
| **技术基础评估** | 看课程成绩 | **看项目中用的技术** |
| **软性指标** | 抽象概念（学习能力等） | **具体行为（6个统一维度）** |
| **岗位区分** | 统一套指标 | ~~技术岗 vs 非技术岗分开~~ → **统一指标，不区分** |
| **评分标准** | 模糊描述 | **具体可观察的行为标准** |
| **路由方式** | 单一路径 | ~~关键词路由判断~~ → **无路由，统一处理** |
| **HR 友好度** | 部分指标难理解 | **所有指标 HR 都能理解** |

## 11. 实施建议

1. **使用统一软性指标 Prompt**：不需要判断岗位类型，所有岗位用同一套指标
2. **技术实践评估**：检查项目 tech_stack，不问课程
3. **评分标准具体化**：每个分数段对应具体行为
4. **HR 友好输出**：综合报告用 HR 能理解的语言
