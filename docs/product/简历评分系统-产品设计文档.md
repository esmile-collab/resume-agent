# 简历评分系统 - 产品设计文档

**版本**：v2.2
**日期**：2026-03-04
**适用场景**：校招/实习生简历评分
**定位**：产品视角的评分逻辑设计

---

## 1. 产品定位

### 1.1 核心价值

为校招求职者提供简历-JD匹配度评分，帮助用户了解简历与目标岗位的匹配程度，并获得可执行的修改建议。

### 1.2 目标用户

| 用户类型 | 痛点 | 核心需求 |
|---------|------|----------|
| **校招/实习生** | 海投效率低、不知道简历哪里差 | 了解匹配度、获得修改建议 |
| **招聘者** | 简历筛选成本高 | 快速判断简历质量 |

---

## 2. 评分框架设计

### 2.1 混合评分策略（v2.2 更新）

```
总分 = 硬性指标(60%) + 软性指标(40%)
```

**设计思路**：
- **硬性指标（60%）**：规则计算，客观准确（实习、项目、学历等）
- **软性指标（40%）**：LLM评估，聚焦核心能力 + 可读性

### 2.2 硬性指标（权重60%）

**核心原则**：工作经验（实习+项目）的相关性 > 一切

#### 2.2.1 维度与权重

| 维度 | 权重 | 评估焦点 |
|------|------|----------|
| **工作经验** | 70% | 实习+项目合并评分，强相关大厂实习=100分 |
| 技术实践 | 15% | 项目技术栈与JD的匹配度 |
| 专业对口 | 10% | 专业与JD要求的相关性 |
| 学历层次 | 5% | 学校层次（含精英校加分机制） |

#### 2.2.1.1 学历层次评分（含精英校加分）

**基础分层**：

| 层次 | 基础分 | 覆盖学校 |
|------|--------|----------|
| **精英Tier** | 100分 + 5分bonus | 清华、北大、哈佛、耶鲁、普林斯顿、斯坦福、MIT、牛津、剑桥 |
| **顶尖985** | 100分 | 复旦、上交、浙大、中科大、南大 |
| **其他985** | 95分 | 其余985高校 |
| **211** | 85分 | 所有211高校 |
| **一本** | 70分 | 省重点一本 |
| **其他** | 50分 | 二本及其他 |

**精英校加分机制**：
- **中国Top2**：清华、北大 → +5分 bonus（满分105分）
- **海外Top8**：哈佛、耶鲁、普林斯顿、斯坦福、MIT（HYPSM）+ 牛津、剑桥（Oxbridge） → +5分 bonus
- **中国Top5**：复旦、上交、浙大、中科大、南大 → 基础100分（无bonus）

**设计原因**：
- 清北+HYPSM+Oxbridge代表全球最顶尖教育水平，在简历筛选中有显著优势
- Top5（复交浙科南）虽顶尖但与清北仍有差距，不设bonus
- Bonus仅5分，避免过度放大学校效应（权重仅5%）

**计算示例**：
- 清华本 → 100 + 5 = **105分**
- 北大本 → 100 + 5 = **105分**
- 哈佛本 → 100 + 5 = **105分**
- 复旦本 → 100分
- 普通985 → 95分
- 211 → 85分

#### 2.2.2 工作经验评分逻辑

根据**岗位卷度**调整评分策略：

| 卷度系数 | 策略 | 典型岗位 |
|----------|------|----------|
| **>0.8（极卷）** | 项目 > 实习 | AI算法、AI研究 |
| **0.5-0.8（较卷）** | 实习和项目并重 | AI产品、后端开发 |
| **<0.5（一般）** | 实习优先 | 运营、设计 |

**卷度** = f(公司层级 × 岗位类别 × 转正机会)

#### 2.2.3 典型场景对比

| 场景 | 高卷度（AI算法） | 中卷度（产品） | 低卷度（运营） |
|------|----------------|---------------|---------------|
| 强相关大厂实习 | 100分 | 100分 | 100分 |
| 弱相关大厂实习+强项目 | 80分 | 80分 | 70分 |
| 弱相关大厂实习（无项目） | 15分 ⚠️ | 35分 | 55分 |
| 无实习+强项目 | 90分 ✅ | 65分 | 70分 |
| 无实习+弱项目 | 25分 | 35分 | 40分 |

**关键差异**：
- 极卷岗位：美团运营实习（15分） < AI开源项目（90分）
- 普通岗位：美团运营实习（55分） > 弱项目（40分）

### 2.3 软性指标（权重40%，v2.2 更新）

**设计原则**：
- 统一指标，HR能理解，所有岗位适用
- **L0/L1 两级分层**：L0一级维度（4个）→ L1二级维度（12个）
- **小数点精度**：LLM评分允许小数点后1位（如85.5分）
- **每个L1维度对应一个关键信息维度**，确保评分有据可依

#### 2.3.1 L0/L1 分层结构

```
软性指标 (40%)
│
├── L0: 可读性 (20%) ──────────────────────────────┐
│    ├── L1: 错别字与语法 (5%)                    │
│    ├── L1: 格式规范 (5%)                        │
│    └── L1: 逻辑清晰度 (10%)                     │
│                                                 │
├── L0: 学习能力 (7%) ───────────────────────────┤
│    ├── L1: 技能掌握速度 (3.5%)                  │
│    └── L1: 技能掌握广度 (3.5%)                  │
│                                                 │
├── L0: 执行能力 (7%) ───────────────────────────┤
│    ├── L1: 项目完成度 (3.5%)                    │
│    └── L1: 主导程度 (3.5%)                      │
│                                                 │
├── L0: 数据意识 (3%) ───────────────────────────┤
│    └── L1: 量化能力 (3%)                        │
│                                                 │
└── L0: 稳定性 (3%) ─────────────────────────────┘
     └── L1: 职业规划清晰度 (3%)
```

#### 2.3.2 L1 维度详细评分标准

##### L0: 可读性 (20%)

**L1: 错别字与语法 (5%)**

| 分数 | 标准 | 示例 |
|---|---|---|
| 100.0 | 无错别字，无语法错误 | 完美 |
| 80.0 | 1-2处错别字或小语法错误 | 偶尔瑕疵 |
| 50.0 | 3-5处错别字或语法错误 | 有明显瑕疵 |
| 20.0 | >5处错别字，语法混乱 | 严重影响阅读 |

**L1: 格式规范 (5%)**

| 分数 | 标准 | 示例 |
|---|---|---|
| 100.0 | 排版整齐、层次清晰、标点正确 | 专业简历格式 |
| 70.0 | 格式基本规范，小部分不一致 | 总体整洁 |
| 40.0 | 格式混乱、层次不分、标点错误 | 难以阅读 |

**L1: 逻辑清晰度 (10%)**

| 分数 | 标准 | 示例 |
|---|---|---|
| 100.0 | STAR结构完整，时间线连贯，因果关系明确 | 背景-任务-行动-结果完整 |
| 80.0 | 结构基本清晰，偶有跳跃 | 大部分有STAR结构 |
| 60.0 | 结构部分缺失，时间线混乱 | 部分经历缺少背景或结果 |
| 40.0 | 结构混乱，逻辑断裂 | 难以理解项目全貌 |
| 20.0 | 完全没有逻辑结构 | 碎片化描述 |

##### L0: 学习能力 (7%)

**L1: 技能掌握速度 (3.5%)**

| 分数 | 标准 | 示例 |
|---|---|---|
| 100.0 | 3个月内掌握3+项新技能，自学高难度技术 | 2周学会React+TS+Node.js |
| 70.0 | 按计划学习课程/技术，在项目中应用 | 系统学习Python并完成项目 |
| 40.0 | 学习时间比预期长，需要额外指导 | 跟着教程完成简单项目 |

**L1: 技能掌握广度 (3.5%)**

| 分数 | 标准 | 示例 |
|---|---|---|
| 100.0 | 跨领域掌握多项技能（技术+产品+设计） | 前端+产品+数据分析 |
| 70.0 | 同领域内掌握完整技术栈 | 前端全栈（HTML/CSS/JS/框架） |
| 40.0 | 仅掌握单一技能 | 只会HTML/CSS |

##### L0: 执行能力 (7%)

**L1: 项目完成度 (3.5%)**

| 分数 | 标准 | 示例 |
|---|---|---|
| 100.0 | 主导完成完整项目上线，从0到1负责核心模块 | 独立开发并上线功能 |
| 70.0 | 参与完成项目，负责重要部分，独立完成任务 | 负责后端API开发 |
| 40.0 | 协助完成支持工作，按指令完成任务 | 协助测试和文档 |
| 30.0 | 只有想法未落地，参与讨论但无产出 | 提出建议但无实施 |

**L1: 主导程度 (3.5%)**

| 分数 | 标准 | 示例 |
|---|---|---|
| 100.0 | 项目负责人/核心owner，独立决策 | "主导XX系统开发" |
| 70.0 | 重要参与者，有决策权 | "负责XX模块设计" |
| 40.0 | 执行者，按指示完成任务 | "参与XX开发" |
| 20.0 | 边缘参与者，贡献有限 | "协助XX工作" |

##### L0: 数据意识 (3%)

**L1: 量化能力 (3%)**

| 分数 | 标准 | 示例 |
|---|---|---|
| 100.0 | 量化成果，用数据指导决策 | "留存率提升30%，A/B测试验证" |
| 70.0 | 有数据意识，提到一些数据 | "效果良好，用户增长" |
| 40.0 | 完全没有数据意识 | "效果很好，深受好评" |

##### L0: 稳定性 (3%)

**L1: 职业规划清晰度 (3%)**

| 分数 | 标准 | 示例 |
|---|---|---|
| 100.0 | 职业规划清晰，长期深耕某领域 | "希望在XX领域深耕3-5年" |
| 60.0 | 基本稳定，短期意愿明确 | "愿意尝试XX方向" |
| 30.0 | 不稳定，频繁跳方向 | 6个月内换3个方向 |

#### 2.3.3 LLM 评分精度要求

**v2.2 更新**：允许 LLM 评分使用小数点后1位精度

**评分示例**：
```json
{
  "dimension_scores": [
    {
      "l0_dimension": "可读性",
      "l1_dimension": "逻辑清晰度",
      "score": 85.5,
      "weight": 0.10,
      "reasoning": "大部分经历有STAR结构，但少数项目缺少背景说明"
    },
    {
      "l0_dimension": "学习能力",
      "l1_dimension": "技能掌握速度",
      "score": 92.0,
      "weight": 0.035,
      "reasoning": "2个月内自学React+TypeScript并完成项目"
    }
  ]
}
```

**精度规则**：
- 所有 L1 维度评分允许小数点后1位（0.0-100.0）
- L0 维度分数 = Σ(L1分数 × L1权重)
- 最终软性指标总分 = Σ(L0分数 × L0权重)

#### 2.3.4 调整说明（v2.2）

**相比 v2.1 的改进**：
1. **L0/L1 分层**：将软性指标拆分为12个细粒度 L1 维度，每个维度对应具体信息点
2. **精英校加分**：学历层次增加清北+HYPSM+Oxbridge 的5分bonus机制
3. **小数点精度**：LLM评分允许小数点后1位，提高评分精细度
4. **权重保持不变**：可读性20%、学习能力7%、执行能力7%、数据3%、稳定3%

## 4. 简历修改建议设计

### 4.1 设计原则

**不提供的建议**：
- ❌ "补充XX成果" - 如果有成果用户肯定放了
- ❌ "技能清单突出XX技术" - HR不看重技能清单
- ❌ "量化项目成果" - 如果有数据用户肯定写了

**只提供的建议**：
- ✅ 改表达方式（技术术语→业务语言、过程→结果）
- ✅ ATS关键词优化（缺失关键词、关键词密度、关键词位置）
- ✅ 内容重组（经历排序、项目合并、重点突出）
- ✅ 具体修改示例（Before/After对比）

### 4.2 建议类型

| 类型 | 优先级 | 示例 |
|------|--------|------|
| **ATS关键词缺失** | HIGH | JD核心词"对话系统"在简历中完全缺失 |
| **表达方式优化** | HIGH/MED | 结果描述应先讲业务价值（功能上线）再讲数据 |
| **结构调整** | HIGH | 最相关实习应放在最前面 |
| **关键词密度** | LOW | 某关键词仅在1处出现，建议多处强化 |

### 4.3 建议格式

```
#### 建议1：JD核心关键词'对话系统'在简历中完全缺失，ATS系统可能直接过滤

**位置**：腾讯实习标题

**修改前**：
```
腾讯实习 产品策划/运营（大模型数据策略与评测）
```

**修改后**：
```
腾讯混元大模型产品实习 | 对话系统数据策略与评测负责人
```

**ATS关键词**：对话系统、大模型、产品

---
```

## 5. 产品流程

### 5.1 用户旅程

```
用户输入简历+JD
    ↓
系统解析JD（提取公司、岗位、卷度系数、技术要求）
    ↓
硬性指标规则评分（实习、项目、学历等）
    ↓
软性指标LLM评估（学习能力、执行能力等）
    ↓
生成修改建议（ATS关键词、表达优化、结构调整）
    ↓
输出完整报告
```

### 5.2 核心能力依赖

| 能力 | 实现方式 | 说明 |
|------|----------|------|
| JD解析 | 规则+LLM | 提取公司、岗位、技术要求、计算卷度 |
| 硬性评分 | 规则引擎 | 实习/项目匹配度、学历层次等 |
| 软性评分 | LLM | 学习能力、执行能力等软指标评估 |
| 建议生成 | 规则引擎 | ATS关键词检测、表达优化、结构调整 |

## 6. 数据与指标

### 6.1 核心指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 评分准确性 | 与人工评分一致性 > 85% | 通过50样本评测集验证 |
| 低匹配识别率 | 准确率 > 90% | 纯关键词匹配仅65% |
| 改写后评分提升 | 平均 > 10% | 修改建议的有效性 |
| 单次成本 | < $0.01 | 月成本(1000次) < $10 |
| 响应时间 | < 10秒 | 用户可接受范围 |

### 6.2 评测方法

**自建评测集**：
- 样本量：50+对简历-JD
- 对照标准：开源ATS评分结果
- 评估维度：一致性、低匹配识别准确率
