# UI交互设计（对话优先版）

版本：v2.0  
日期：2026-02-27  
关联文档：MVP_PRD_Resume_Fit_Agent.md、任务路由设计.md、多轮对话设计.md

---

## 1. 设计目标

1. **单对话框完成主流程**：用户主要通过自然语言推进，不依赖多页面跳转。
2. **推荐语言驱动**：系统每一步给出明确建议和下一句可说的话。
3. **按钮最小化**：快捷操作仅作兜底，不作为主路径。
4. **状态可见但不打扰**：用户看到“当前阶段、当前方向、下一步建议”，无需理解状态机细节。
5. **信息卡保留**：保留 loading 进度反馈与评分卡展示，去掉的是操作按钮，不是可视化信息。

---

## 2. v0.3 对齐规则（必须）

1. JD 原文归属 `Project`，Task Card 仅持 JD 引用关系。
2. 批量 JD 先预览再确认创建/更新卡片。
3. 卡片内新增 JD 事件上收到 Project 分配器。
4. 评分是建议，不是阻断；低匹配需风险确认。
5. 交互默认自然语言确认（如“确认创建”“继续生成”）。
6. 必须保留 JD 解析/聚类/评分/生成的 loading 反馈与结果卡片。

---

## 3. 交互形态

### 3.1 主界面结构（单窗口）

1. 主区：聊天流（系统推荐语 + 用户回复 + 结果卡片）。
2. 侧区（可折叠）：
- 当前 Project 基础信息
- 当前 Task Card
- 关联 JD 摘要
- 当前评分与版本号

### 3.2 交互原语

1. **系统推荐语**（主引导）
- 示例："我识别到 10 条JD，聚为 2 个方向。你可以回复'确认创建'来生成卡片。"
2. **用户自然语言回复**（主操作）
- 示例："先处理策略方向"、"确认创建"、"继续生成"。
3. **快捷短语（可选）**
- 示例：`确认创建`、`先看分配明细`、`取消`
- 说明：是输入建议，不是传统功能按钮。

## 4. 关键对话流程

### 4.1 Project 初始化

```text
系统：欢迎，你可以先上传基础简历和JD。
用户：这是我的简历和10条JD。
系统：已收到。正在解析简历并拆分JD...
```

### 4.2 批量 JD 预览与确认

```text
系统：正在拆分JD（步骤 1/3）...
系统：正在进行方向聚类（步骤 2/3）...
系统：正在生成归属建议（步骤 3/3）...

系统：我识别到 10 条JD，聚类为 2 个方向：
- 策略产品（6）
- 功能产品（4）

建议创建2张任务卡。你可以回复：
- “确认创建”
- “先看分配明细”
- “取消”

用户：先看分配明细
系统：已展示每条JD的归属建议与理由。
用户：确认创建
系统：已创建/更新2张任务卡，并开始评分。
```

### 4.3 评分后推荐引导（高/中匹配）

```text
系统：策略方向当前 82/100（高匹配）。
建议：可以直接生成，也可以先补1条更量化的数据。
你可以直接告诉我“直接生成”或“我先补充信息”。

用户：直接生成
系统：好的，正在生成策略方向简历。
```

### 4.4 低匹配风险确认

```text
系统：内容运营方向 38/100（低匹配）。
差距主要在业务经历与可复述证据。
如果继续，我会进入补偿模式（不虚构经历）。
请回复“确认继续”或“先看提升建议”。

用户：确认继续
系统：已进入补偿模式，开始生成。
```

### 4.5 卡片内新增 JD（上收分配）

```text
用户：我在这个方向再补一条JD。
系统：收到，我会按Project规则判断归属。
结果：这条JD更匹配“功能产品”卡片，已完成迁移并更新该卡评分。
```

## 5. 系统推荐语模板库

### 5.1 聚类预览

1. "我识别到 `{jd_count}` 条JD，主要是 `{direction_count}` 个方向。建议先创建对应任务卡。"
2. "我已经给出每条JD的归属建议。若没问题，回复‘确认创建’。"

### 5.2 评分阶段

1. "当前方向 `{score}/100`，我建议你先 `{next_action}`。"
2. "如果你愿意，我可以先追问2个补充问题，把这版再提一档。"

### 5.3 风险确认

1. "继续可以做，但属于低匹配投递。我会启用补偿模式并标注风险。"
2. "请回复‘确认继续’或‘先看提升建议’。"

### 5.4 版本管理

1. "已生成 v{version_no}，并设为当前最终版。"
2. "如果要基于新简历重做，请直接说‘用最新简历重生成策略方向’。"

## 6. 保留的可视化信息层（必须）

### 6.1 Loading 反馈（保留）

在以下阶段都展示进度状态：
1. JD拆分中（如：`步骤 1/3`）
2. 方向聚类中（如：`步骤 2/3`）
3. 分配预览生成中（如：`步骤 3/3`）
4. 评分中（维度计算进度）
5. 简历生成中（normal/compensation）

示例文案：
1. “正在解析第 7/10 条 JD...”
2. “正在计算策略方向匹配度（业务/能力/真实性/可复述性）...”
3. “正在生成 v3 版本，请稍候...”

### 6.2 评分卡展示（保留）

评分卡以信息卡形式展示，不依赖按钮操作：
1. 总分与分层：`82/100 (high)`。
2. 维度分：业务/能力/真实性/可复述性。
3. 差距证据：关键不匹配点。
4. 推荐语：下一步建议（用户可直接语言回复）。

示例：
1. “当前评分 67/100，中匹配。建议先补1条可量化结果；若你想直接生成，也可以回复‘直接生成’。”

### 6.3 风险确认展示（保留）

低匹配场景下展示风险卡，但用自然语言确认推进：
1. 系统展示风险说明与补偿模式说明。
2. 用户回复“确认继续”或“先看提升建议”。

---

## 7. 表单替代策略（对话采集）

原则：不用固定大表单，改为分步提问。

示例：
1. "你这段经历最能体现哪项能力？"
2. "有可量化结果吗？比如提升了多少、节省了多少？"
3. "这段经历面试里最容易被追问什么？"

说明：每次只问1-2个问题，减少用户负担和一次性输入压力。

---

## 8. 按钮策略（降级方案）

1. 默认不展示复杂按钮矩阵。
2. 仅保留少量“回复建议词”（chips）帮助用户快速输入。
3. 当模型判断不确定时，才显示 2-3 个澄清选项（仍可自然语言回答）。

---

## 9. 评估指标（UI维度）

1. 无按钮路径完成率（仅自然语言完成流程的占比）。
2. 平均点击数（目标持续下降）。
3. 推荐语采纳率（用户按推荐短语推进的比例）。
4. 澄清轮次（每个任务平均澄清次数）。
5. 对话中断率（流程中途退出比例）。

---

## 10. 结论

这版 UI 的核心不是“功能入口”，而是“对话编排”。
产品形态是一个会主动给下一步建议的求职决策对话框，而不是传统多按钮工具页。
