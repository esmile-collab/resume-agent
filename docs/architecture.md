## 模块与协作依据

| 模块 | 对应文件 | 接口与边界 |
| --- | --- | --- |
| 界面与接口 | [src/api/main.py](../src/api/main.py) | 会话接口调用 runtime；资料、产物编辑、差异与导出接口直接访问 runtime.memory，保留两条真实调用路径。 |
| 会话运行时 | [src/agent/runtime.py](../src/agent/runtime.py) | 读写记忆，向 Planner 传入消息与快照，按计划调用工具；通过 RunTraceCRUD 直接记录工具输入和 observation。 |
| 规划器 | [src/agent/planner.py](../src/agent/planner.py) | 基于规则识别意图，输出工具计划。生成和润色计划先评分；当前没有单轮自主重规划。 |
| 工具注册表 | [src/agent/tools.py](../src/agent/tools.py) | 封装 JD 入库、评分、生成和润色，组合领域能力与 MemoryManager；负责登记相应报告和产物版本。 |
| 领域能力 | [src/services/patcher.py](../src/services/patcher.py) | 评分器、JDAnalyzer、Parser、Patcher 等提供独立业务函数。当前润色为规则改写，事实与职责表述仍需人工核对。 |
| 记忆与产物 | [src/agent/memory.py](../src/agent/memory.py) | 管理画像、经历、岗位方向、快照、版本、差异与导出；经 CRUD 与文件持久化。编辑产物尚未自动回流重评分。 |

## 随代码维护

模块职责、调用方、输入输出、共享校验、持久化或回流方式变化时，在同一提交中更新 SVG、README 和本文。不要将人工操作写成自动模块，也不要删除仍然存在的耦合关系。
图片仅显示简短模块名。使用细框线和充分间距，保持简洁图例；具体职责、接口、路径与限制维护在本文。
提交前检查 XML 解析、文字边界、连线与节点、README 引用以及静态资源大小。代码行为没有变化时无需为图增加运行依赖。
