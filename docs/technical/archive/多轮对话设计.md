# 多轮对话设计

版本：v1.1  
日期：2026-02-27  
关联文档：MVP_PRD_Resume_Fit_Agent.md、任务路由设计.md、UI交互设计.md

---

## 1. 设计目标

1. 自然交互：用户可以用自然语言，不依赖按钮才能完成流程。
2. 过程可控：每轮对话都映射到明确意图和状态转移。
3. 乱序可处理：用户不按引导输入时，仍能保持任务连续。
4. 降低误执行：不确定时先澄清，不做猜测式执行。

---

## 2. 与 PRD v0.3 对齐边界

1. 对话在 `Task Card` 内进行，默认只作用于当前卡片。
2. 用户补充经历只写入当前卡片私有信息，不自动同步到其他卡片。
3. 意图保持 6 个：`ingest_jd/update_resume/add_info/generate/compare/abandon`。
4. 评分是建议信号，不是阻断；低匹配走“风险确认 -> 补偿生成”。
5. JD 原文归属 `Project`；卡片内“新增JD”只作为入口，底层仍走 Project 分配器。

---

## 3. 意图识别策略（无硬阈值）

### 3.1 识别顺序

1. `UI 显式动作优先`：按钮点击直接映射意图，不走自然语言分类。
说明：MVP 默认不依赖按钮；该规则仅用于存在快捷词/快捷按钮时的兜底映射。
2. `强规则识别`：命令词和结构化输入直接命中意图。
3. `状态约束修正`：结合当前 `task_state` 过滤不可能意图。
4. `LLM 判别`：仅在前3步不能唯一确定时使用。
5. `澄清问题`：仍不确定就返回候选动作供用户选择。

### 3.2 意图输出结构

```json
{
  "primary_intent": "generate",
  "candidates": ["generate", "add_info"],
  "need_clarification": false,
  "clarify_question": ""
}
```

说明：
1. 不依赖固定数值阈值驱动路由。
2. 仅保留候选意图用于可解释性和日志分析。

### 3.3 规则示例

```python
def classify_intent(user_input: str, ctx: DialogContext) -> IntentResult:
    # 1) UI 显式动作
    if ctx.ui_action:
        return IntentResult(primary_intent=ctx.ui_action, candidates=[ctx.ui_action], need_clarification=False)

    # 2) 强规则
    if has_jd_attachment(ctx):
        return IntentResult(
            "ingest_jd",
            ["ingest_jd"],
            False,
            metadata={
                "source_scope": ctx.current_scope,  # project|task_card
                "source_task_card_id": ctx.current_task_card_id,
            },
        )
    if has_resume_attachment(ctx):
        return IntentResult("update_resume", ["update_resume"], False)
    if contains_any(user_input, ["生成", "改简历", "优化"]):
        return IntentResult("generate", ["generate", "add_info"], False)

    # 3) LLM 判别（仅兜底）
    llm = llm_disambiguate(user_input, ctx)
    if llm.need_clarification:
        return IntentResult(
            primary_intent=llm.candidates[0],
            candidates=llm.candidates,
            need_clarification=True,
            clarify_question=llm.clarify_question,
        )

    return IntentResult(llm.candidates[0], llm.candidates, False)
```

## 4. 对话状态管理

### 4.1 对话状态

1. `idle`：等待用户输入。
2. `processing`：识别并执行意图。
3. `clarifying`：等待用户澄清。
4. `waiting_confirm`：等待风险确认。
5. `error_recovery`：执行失败后的恢复。

### 4.2 任务状态（沿用路由文档）

1. `pending`
2. `scored`
3. `generating`
4. `completed`
5. `abandoned`

### 4.3 核心转移

```text
idle -> processing ->
  - (意图明确) 执行 -> idle
  - (意图不明确) clarifying -> processing
  - (低匹配生成) waiting_confirm -> processing
  - (异常) error_recovery -> idle
```

## 5. 乱序输入处理

### 5.1 规则

1. 在卡片 A 补充信息时用户发送新 JD：
- 触发 `ingest_jd(source_scope=task_card)`，事件上收到 Project 分配器。
- Project 分配器返回：加入当前卡 / 迁移已有卡 / 新建卡。
- 卡片 A 当前结果不被覆盖。

2. 在已完成卡片继续补充经历：
- 写入该卡片私有 memory。
- 不自动重生成，等待用户显式触发 `generate`。

3. 用户更新基础简历：
- 写入 `Project` 新版本。
- 提示“可在指定卡片手动重生成”，不自动覆盖已完成卡片。

4. 用户跨卡切换：
- 上下文载入“Project 基础简历版本 + 当前卡片私有信息”。

5. 用户在 Project 一次上传多个 JD：
- 先返回“聚类预览”而不直接创建卡片；
- 用户确认后再执行批量创建/更新卡片与 JD 归属。

### 5.2 典型冲突处理

```python
def handle_out_of_order(event, current_card):
    if event.type == "ingest_jd" and current_card.is_waiting_info:
        return "route_to_project_allocator", "检测到新JD，已进入Project分配流程"

    if event.type == "profile_supplement" and current_card.status == "completed":
        return "append_card_memory", "补充已记录，可手动触发重新生成"

    return "continue_current_card", "已在当前卡片继续处理"
```

## 6. 低匹配风险确认流程

### 6.1 触发条件

- 当前卡片 `match_level=low`
- 用户触发 `generate`

### 6.2 交互流程

1. 展示低匹配风险与差距证据。
2. 用户选择：`确认生成` 或 `取消`。
3. 选择确认：进入 `generating(mode=compensation)`。
4. 选择取消：返回 `scored`，给出补充建议。

## 7. 对话示例

### 7.1 信息缺失澄清

```text
用户：生成简历
系统：你当前有2个方向卡片，先生成哪一个？
1. 策略产品（82）
2. 功能产品（67）
```

### 7.2 低匹配风险确认

```text
用户：生成内容运营方向简历
系统：当前匹配度 38/100，若继续将进入补偿模式（不虚构经历）。是否确认？
用户：确认
系统：已进入补偿模式，开始生成。
```

### 7.3 乱序输入

```text
用户：我再补充一个项目经历
用户：另外我这边还有一条策略岗JD
系统：已识别到新JD，正在按Project规则分配。
系统：该JD更匹配“策略产品”方向，已建议新建卡片；当前卡片补充已保存。
```

## 8. 数据埋点

| 埋点项 | 说明 |
|---|---|
| `dialog_turn_count` | 对话轮次分布 |
| `clarification_trigger_rate` | 澄清触发率 |
| `clarification_resolution_rate` | 澄清后成功落单一意图的比例 |
| `risk_confirm_accept_rate` | 低匹配风险确认通过率 |
| `out_of_order_recovery_rate` | 乱序输入恢复成功率 |
| `manual_regenerate_rate` | 基础简历更新后手动重生成比例 |

## 9. 演进路线

### MVP（当前）

1. 规则优先的意图识别。
2. 澄清式兜底，不使用固定置信度阈值。
3. 卡片内多轮对话和乱序恢复。

### v1.1

1. 基于历史日志优化澄清问题模板。
2. 提升跨卡切换时的上下文恢复速度。

### v2.0

1. 基于用户行为学习常见操作路径。
2. 提升复杂输入（混合多个动作）的一次识别准确率。
