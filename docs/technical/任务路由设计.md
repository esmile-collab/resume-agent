## 1. 设计目标

1. **职责分离**：评分系统专注于评估，任务路由专注于决策
2. **意图优先**：路由由用户意图驱动，评分只作为风险信号
3. **简化复杂度**：最少的意图和状态，最清晰的决策逻辑
4. **用户控制权**：低匹配时允许用户继续（带风险提示）

## 2. 架构定位

```

补充边界（与PRD v0.3对齐）：
1. `Project` 共享层保存基础简历、项目元信息与JD资产池。
2. `Task Card` 私有层保存该方向补充信息，不跨卡自动同步。
3. `update_resume` 更新的是基础简历版本，不自动覆盖已完成卡片结果。
4. JD 原文和解析结果属于 `Project` 资产池，`Task Card` 仅保存 JD 引用关系。
┌─────────────────────────────────────────────────────────┐
│                    用户输入                               │
│              简历 + JD（可多个）                          │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│                 评分系统（独立模块）                       │
│  输出：S100分数 + 4个核心维度 + 评级 + 投递建议            │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│                任务路由（本模块）                         │
│  意图分类 + 状态管理 + 决策执行                          │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│              认知补偿（低匹配仍生成时）                    │
│  生成个人陈述、求职信等补偿内容                           │
└─────────────────────────────────────────────────────────┘
```

## 3. 意图定义（6个核心意图）

### 3.1 意图列表

| 意图ID | 触发方式 | 路由目标 | 说明 |
|---|---|---|---|
| `ingest_jd` | 用户添加JD（Project或Task Card入口） | JD入Project资产池 → 分配到卡片 → 评分 | 可单个或批量 |
| `update_resume` | 用户更新简历 | 替换简历 → 重评 | 覆盖原简历 |
| `add_info` | 用户补充信息 | 回填Memory → 重评 | 仅当前任务卡片，不跨卡同步 |
| `generate` | 用户请求生成（自然语言或快捷词） | 进入生成流程 | 根据score自动判断模式 |
| `compare` | 用户请求对比方向 | 输出方向优先级 | 需≥2个方向 |
| `abandon` | 用户放弃任务 | 标记为已放弃 | 可恢复 |

### 3.2 入口别名规则

1. 卡片内“新增JD（add_jd）”不新增意图，统一映射为 `ingest_jd`。
2. 通过 `source_scope` 标识入口：`project|task_card`。
3. 若 `source_scope=task_card`，必须携带 `source_task_card_id`，用于优先尝试“加入当前卡片”。

### 3.3 意图简化说明

**移除的意图及原因**：

| 移除意图 | 原因 | 替代方案 |
|---|---|---|
| `request_rescore` | 自动触发，不需要用户明确请求 | 数据变更时自动重评 |
| `request_explain` | 解释信息内嵌在评分卡片 | UI直接展示 |
| `request_force_generate` | 与`request_generate`合并 | 根据score自动判断 |

**合并的意图**：

| 原意图 | 合并为 | 逻辑 |
|---|---|---|
| `request_generate` + `request_force_generate` | `generate` | high/medium直接生成，low弹风险确认 |

## 4. 状态机设计（5个核心状态）

### 4.1 状态定义

| 状态 | 说明 | 属性 | 可用操作 |
|---|---|---|---|
| `pending` | 等待评分 | - | - |
| `scored` | 已评分 | `match_level`: high/medium/low<br>`score`: 0-100 | 全部操作 |
| `generating` | 生成中 | `mode`: normal/compensation | - |
| `completed` | 已完成 | `has_compensation`: bool | 查看/重新生成 |
| `abandoned` | 已放弃 | - | 恢复 |

### 4.2 状态转移图

```
pending
    ↓ [评分完成]
scored
    ↓ [用户操作触发]
    ├──→ [generate + high/medium] → generating (normal) → completed
    ├──→ [generate + low + 确认] → generating (compensation) → completed
    ├──→ [generate + low + 取消] → scored (保持)
    ├──→ [ingest_jd / update_resume / add_info] → scored (重新评分)
    ├──→ [compare] → scored (保持，输出对比)
    └──→ [abandon] → abandoned
```

### 4.3 状态简化说明

**合并的状态**：

| 原状态 | 合并为 | 说明 |
|---|---|---|
| `high_match` | `scored` + `match_level=high` | 用属性区分，而非独立状态 |
| `medium_match` | `scored` + `match_level=medium` | 同上 |
| `low_match` | `scored` + `match_level=low` | 同上 |
| `compensation` | `generating` + `mode=compensation` | 用属性区分 |

## 5. 路由矩阵（Intent × State）

| Intent | 允许状态 | 主要工具链 | 结果状态 |
|---|---|---|---|
| `ingest_jd` | 任意 | JD切分 → 方向聚类/匹配 → Project级分配器 → 评分 | `scored` |
| `update_resume` | 任意 | 简历解析 → 全量重评 | `scored` |
| `add_info` | `scored` | TaskCard Memory回填 → 当前卡片重评 | `scored` |
| `generate` | `scored` | 根据match_level分支（见5.1） | `generating` |
| `compare` | `scored`（≥2个方向） | 方向对比器 | `scored` |
| `abandon` | 任意 | 状态机控制器 | `abandoned` |

### 5.1 ingest_jd 的分配逻辑（Project级）

```text
ingest_jd触发
    ↓
写入Project JD资产池（单条或批量）
    ↓
if 批量或方向不明确:
    JD切分 + 方向聚类 + 预览
    ↓
    用户确认创建/更新卡片
    ↓
project_jd_allocator 逐条分配
    ├── assign_current_card
    ├── assign_existing_card
    └── create_new_card
    ↓
对受影响卡片触发评分更新
```

### 5.2 generate意图的分支逻辑

```
generate意图触发：
    ↓
判断match_level
    ↓
├── high/medium → normal_generate
└── low → await_risk_ack
              ↓
         用户选择
              ↓
         ├── 确认 → compensation_generate
         └── 取消 → 回到scored
```

### 5.3 交互约束（必须）

1. JD偏离方向提醒：
- 当卡片内新JD与当前方向显著偏离时，提示“新建卡片或迁移到其他卡片”。
2. JD分配统一上收：
- Task Card 内新增JD也必须走 Project 分配器，不允许直接写入当前卡片。
3. 批量JD预览确认：
- 批量上传先展示聚类预览，用户确认后再创建/更新卡片。
4. 评分不阻断生成：
- 评分仅影响建议路径，低匹配通过风险确认后仍可生成。
5. 版本锁定：
- 每次生成都创建版本号，卡片显示“当前最终版”。
6. 基础简历更新策略：
- 更新基础简历后，仅提示可手动重生成；不自动覆盖已完成卡片。

## 6. 决策逻辑

### 6.1 总体决策函数

```python
def route_task(intent: Intent,
               task_state: TaskState,
               score_card: Optional[ScoreCard] = None,
               source_scope: str = "task_card",
               source_task_card_id: Optional[str] = None,
               jd_payload: Optional[dict] = None) -> RouteDecision:
    """基于意图+状态进行决策"""

    # 1) JD接入：统一走Project分配器
    if intent == Intent.INGEST_JD:
        return handle_ingest_jd(
            source_scope=source_scope,
            source_task_card_id=source_task_card_id,
            jd_payload=jd_payload,
        )

    # 2) 其他数据变更意图：重算
    if intent in [Intent.UPDATE_RESUME, Intent.ADD_INFO]:
        return RouteDecision(
            state=TaskState.SCORED,
            message="正在重新评分...",
            actions=["查看新评分"]
        )

    # 3) 控制意图
    if intent == Intent.COMPARE:
        return RouteDecision(
            state=task_state,
            message="已输出方向对比",
            actions=["查看对比"]
        )
    if intent == Intent.ABANDON:
        return RouteDecision(
            state=TaskState.ABANDONED,
            message="已放弃",
            actions=[]
        )

    # 4) 生成意图：根据match_level分支
    if intent == Intent.GENERATE:
        return handle_generate(task_state, score_card)

    # 5) 默认：停留在当前状态
    return RouteDecision(
        state=task_state,
        message="请选择操作",
        actions=get_available_actions(task_state, score_card)
    )
```

### 6.2 generate意图处理

```python
def handle_generate(task_state: TaskState, score_card: ScoreCard) -> RouteDecision:
    """处理生成意图"""

    if task_state != TaskState.SCORED:
        return RouteDecision(
            state=task_state,
            message="请先完成评分",
            actions=[]
        )

    match_level = score_card.match_level  # "high" | "medium" | "low"

    # high/medium：直接生成
    if match_level in ["high", "medium"]:
        return RouteDecision(
            state=TaskState.GENERATING,
            mode="normal",
            message="正在生成简历...",
            actions=[]
        )

    # low：返回风险确认
    if match_level == "low":
        return RouteDecision(
            state=TaskState.SCORED,
            await_risk_ack=True,  # 标记需要风险确认
            message=f"匹配度较低（{score_card.score}/100），请确认是否继续",
            actions=["确认生成", "取消"]
        )
```

### 6.3 ingest_jd 处理

```python
def handle_ingest_jd(source_scope: str,
                     source_task_card_id: Optional[str],
                     jd_payload: dict) -> RouteDecision:
    """处理JD接入：写Project，再分配到卡片"""

    split_result = jd_splitter(jd_payload)
    cluster_result = direction_cluster(split_result)

    # 批量或方向不明确，先返回预览等待用户确认
    if cluster_result.need_preview_confirm:
        return RouteDecision(
            state=TaskState.SCORED,
            message="已生成方向预览，请确认创建/更新卡片",
            actions=["确认创建", "调整后确认", "取消"]
        )

    allocation = project_jd_allocator(
        source_scope=source_scope,
        source_task_card_id=source_task_card_id,
        split_result=split_result,
        cluster_result=cluster_result
    )

    return RouteDecision(
        state=TaskState.SCORED,
        message=f"JD已分配：{allocation.summary}",
        actions=["查看受影响卡片评分"]
    )
```

### 6.4 风险确认处理

```python
def handle_risk_acknowledgement(confirmed: bool,
                                score_card: ScoreCard) -> RouteDecision:
    """处理用户对低匹配的风险确认"""

    if confirmed:
        return RouteDecision(
            state=TaskState.GENERATING,
            mode="compensation",  # 补偿模式
            message="⚠️ 已切换到补偿模式，正在生成...",
            warning=True,
            actions=[]
        )
    else:
        return RouteDecision(
            state=TaskState.SCORED,
            message="已取消",
            actions=["查看评分", "查看提升建议"]
        )
```

## 7. 代码结构

```python
from enum import Enum
from dataclasses import dataclass
from typing import Optional, List

class TaskState(Enum):
    PENDING = "pending"
    SCORED = "scored"
    GENERATING = "generating"
    COMPLETED = "completed"
    ABANDONED = "abandoned"

class MatchLevel(Enum):
    HIGH = "high"      # S100 >= 75
    MEDIUM = "medium"  # 50 <= S100 < 75
    LOW = "low"        # S100 < 50

class Intent(Enum):
    INGEST_JD = "ingest_jd"
    UPDATE_RESUME = "update_resume"
    ADD_INFO = "add_info"
    GENERATE = "generate"
    COMPARE = "compare"
    ABANDON = "abandon"

@dataclass
class ScoreCard:
    score: int
    match_level: MatchLevel
    dimensions: List[Dimension]
    suggestion: str

@dataclass
class RouteDecision:
    state: TaskState
    message: str
    actions: List[str]
    mode: Optional[str] = None  # "normal" | "compensation"
    warning: bool = False
    await_risk_ack: bool = False  # 是否需要风险确认

class TaskRouter:
    def __init__(self, scoring_system):
        self.scoring = scoring_system

    def route(self,
              intent: Intent,
              task_state: TaskState,
              score_card: Optional[ScoreCard] = None) -> RouteDecision:
        """路由决策函数"""
        return route_task(intent, task_state, score_card)

    def handle_risk_ack(self, confirmed: bool, score_card: ScoreCard) -> RouteDecision:
        """处理风险确认"""
        return handle_risk_acknowledgement(confirmed, score_card)
```

## 8. UI层配合（对话优先）

UI 主路径为自然语言交互，按钮仅作兜底快捷词：

```python
# UI层伪代码（对话驱动）
class UIService:
    def __init__(self, task_router: TaskRouter, intent_classifier):
        self.router = task_router
        self.classifier = intent_classifier

    def on_user_message(self, text: str, ctx: DialogContext):
        # 1) 分类意图
        intent_result = self.classifier.classify(text, ctx)

        # 2) 生成路由决策
        decision = self.router.route(
            intent=intent_result.intent,
            task_state=ctx.task_state,
            score_card=ctx.score_card,
            source_scope=intent_result.source_scope,
            source_task_card_id=intent_result.source_task_card_id,
        )

        # 3) 用推荐语言回给用户下一步
        return self.render_recommendation(decision)
```

说明：
1. 系统每一步给出可执行推荐语，用户直接回复自然语言推进。
2. 风险确认同样通过自然语言完成（如“确认继续”）。
3. 快捷词可展示，但不应成为主路径依赖。
